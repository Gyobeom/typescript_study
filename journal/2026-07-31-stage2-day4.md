## 배운 것

- SOLID에 대해서 배웠고, 각 원칙에 따른 구분방법에 대해서 배웠음.
- SRP 한 클래스는 바뀌는 이유를 한가지만, SRP의 정의는 클래스가 한개의 기능을 가지고 있다는게 아니라 변경이 되어야할 이유가 하나라는 것, ex) 한 클래스에, 검증|계산|저장|알림들을 다한다면 각 기능들이 변경 될 때마다 클래스의 내용도 변경이 이루어져야함. 한개의 기능을 수행하는데 여러개의 메소드를 사용하는 것은 가능.
- OCP 확장에는 열리고 수정에는 닫혀라, 새기능이 추가될 때마다 기존 코드를 고치지말고 새코드를 추가하는 방식으로 끝나야 한다. switch 문처럼 새로운 기능이 늘어날 때마다 조건을 붙여서 하게 되면 기존 케이스를 꺠드릴 위험 존재
- DIP 고수준은 구체가 아니라 추상에 의존하라. function shippingFee(policy: ShippingPolicy...) 여기서 ShippingPolicy가 만약 추상이 아니고, 구체라면, 신규 구체가 생길 때마다 해당 값을 수정해줘야한, 인터페이스라면 별도의 수정없이 그대로 사용할 수 있음
- DIP(원칙) 구체 말고 추상에 의존하라는 설계규칙
- DI(기법) 외부에서 실현 구현체를 넣어주는 방법 = 의존성 주입
